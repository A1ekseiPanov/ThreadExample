# MapReduce

### Задача:

Необходимо разработать программу, которая будет имитировать [MapReduce](https://ru.wikipedia.org/wiki/MapReduce)
фреймворк. В реальности в MapReduce используются независимые ноды, которые общаются между собой по сети и имеют общее
хранилище, у нас же это будут отдельные потоки. В нашей программе будет несколько потоков, которые работают
одновременно: один Coordinator и один или несколько Worker’ов. Задача координатора - это раздача задач для воркеров.
Задачи могу быть двух видов - это map задача, которая производит набор key value пар из входящего файла и записывает их
в промежуточные файлы, и reduce задачи, которые производят финальные файлы с обработанной и отсортированной в алфавитном
порядке информацией. При этом для распаралелливания обработки у нас может быть m reduce задач.
Рассмотрим пример. Нам необходимо посчитать количество разных слов в n файлах.
На вход в нашу программу подаются эти файлы. Далее запускается какое-то количество воркеров (количество может
настраиваться отдельным параметром).

***Рассмотрим работу воркера и задачу map.***
Воркеры запрашивают задачи у координатора и он выдает им по одной map задаче (т.е. по одному фалу), а также прикладывает
уникальный id задачи, имя файла для обработки и количество reduce задач. Далее воркер получает эту задачу, считывает
содержимое файла и передает его в функцию map. Пример функции и её сигнатура указаны ниже:

```
public List<KeyValue> map(String fileName, String content) {
    // разделяем content на слова и для каждого слова создаем объект KeyVal
    // где key - это слово, а value - это "1". И возвращаем список этих объектов
}
```

Как видите тут есть упрощение, мы сразу принимаем на вход содержимое в виде строки, что может быть не очень эффективно,
но для простоты обойдемся и этим. Дальше воркер должен получить список KeyValue и записать каждый такой объект в свой
промежуточный файл. Воркеру необходимо разделить ключи по m бакетам (файлам), где m - это количество reduce задач, таким
образом, чтобы одинаковые ключи попали в один и тот же бакет (файл). Это очень напоминает работу HashMap. В итоге мы
получим m файлов с key value парами. Например, в нашем случае это будут слова в качестве ключей и 1 в качестве значения.
После чего воркер может передать результат задачи в координатор.

***Далее переходим к координатору.***
После того как координатор раздал все map задачи воркерам, он должен дождаться пока они не выполнят их все. Только после
этого он может приступать к раздаче reduce задач. Как только к нему придёт воркер за новой задачей, то он координатор
должен понять какую задачу отдать ему, если все map задачи были завершены, то он может отдать ему первую reduce задачу и
передать список промежуточных файлов, которые были сделаны воркерами на этапе map задач. Как только все reduce задачи
будут завершены, то координатор может сказать воркерам, чтобы они завершили свою работу.

***Рассмотрим теперь reduce задачу***
На вход воркер получает номер reduce задачи и список файлов для обработки. Прежде всего ему нужно вычитать все key value
пары из всех файлов, а дальше отсортировать их в памяти по ключу. После чего все значения с одинаковым ключем передать в
функции reduce. Пример функции reduce и её сигнатура ниже:

```
public String (String key, List<String> values) {
    return String.valueOf(values);
}
```

Как видим, функция reduce для набора значений возвращает одно значение. После чего результат надо записать в финальный
файл в формате “key result” и сообщить координатору, что reduce задача завершена.

***Hints***

1. Промежуточные файлы могут иметь имя mr-X-Y, где X - это уникальный номер map задачи, а Y - это номер reduce задачи

2. Для того, чтобы узнать номер reduce задачи и в какой файл поместить пару ключ значение на стадии map можно
   возмользоваться hashCode от String и поделить по модулю m, где m - это количество reduce задач.

3. В принципе координатор не знает о воркерах ничего, и ему нужно устанавливать какой-то timeout на ожидаение ответа от
   воркера. Ведь воркер может упасть и тогда координатор не сможет завершить MapReduce задачу. Это необязательная часть,
   но можно подумать над тем, как обеспечить надежность.
